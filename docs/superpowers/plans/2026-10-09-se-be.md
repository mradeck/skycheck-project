# SkyCheck v118 — Schweden und Belgien — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Zwei neue Länder-Varianten `skycheck-se` und `skycheck-be` mit amtlichen Geozonen als Snapshot und befristeten Gebieten live auf Knopfdruck.

**Architecture:** Beide Länder nutzen die bestehende ED-269-Strecke (Build-Skript → `data/uas-zones-<cc>.json` → Function `zones-ed269` → gemeinsamer Client-Adapter). Neu sind zwei Umwandler, zwei Live-Proxys und die Verallgemeinerung des norwegischen NOTAM-Knopfs auf eine Länder-Tabelle.

**Tech Stack:** Node ≥ 18 (`node --test`), Netlify Functions (CommonJS), GitHub Actions, Leaflet, Single-File-HTML/JS. Keine neuen Abhängigkeiten.

**Spec:** `docs/superpowers/specs/2026-10-09-se-be-design.md` — sie enthält die exakten Layer, Filter, Feldzuordnungen, Einstufungen, Texte und Werte. Jede Task setzt den für sie genannten Spec-Abschnitt vollständig um; der Plan wiederholt diese Details nicht.

## Global Constraints

- Branch `feature/v118-se-be`. Nur lokale Commits. **Kein `git push`, kein Merge, kein Tag.**
- Commit-Messages enden mit `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Keine neuen Abhängigkeiten, kein `package.json`.
- `skycheck.html` (~9.500 Zeilen) nie ganz lesen: Anker per `grep -n` suchen, Trefferzahl prüfen, ~40 Zeilen Umfeld lesen, editieren.
- Syntaxcheck nach jeder Änderung an `skycheck.html`: `awk '/<script>$/{f=1;next} /<\/script>/{f=0} f' skycheck.html > "$TMPDIR/check.js" && node --check "$TMPDIR/check.js" && echo SYNTAX-OK`
- Ganze Suite: `node --test "tests/*.test.mjs"` (vorher 147/147). Vor jedem Commit grün gesehen haben.
- TDD: Tests zuerst, Fehlschlag sehen, dann Code.
- Zonenform zwischen Functions und Client: `{ name, type, lower, upper, legal, legalUrl, color, desc, geometry }`, Koordinaten `[lon, lat]`; Farben `PROHIBITED` `#ef4444`, `REQ_AUTHORISATION` `#f59e0b`, `CONDITIONAL` `#f97316`, `NO_RESTRICTION` `#3b82f6`, inaktiv/sonst `#64748b`.
- Belgien: **jede** WFS-Abfrage trägt einen `cql_filter`, der `type_code = 'TIME_ZONE'` ausschließt (ungefiltert 149 MB).
- Alle Fremddaten, die in HTML landen, laufen durch `escapeHtml`.
- Bestehendes Verhalten der zwölf vorhandenen Länder bleibt unverändert; für Norwegen ist das in Task 4 ausdrücklich zu belegen.
- Die Ausfall-Logik aus v26.10.117.1 (`fetchZones`, Platzhalter, strict-Modus) wird nicht verändert.
- `APP_VER` wird erst in Task 5 geändert.
- Rohdaten-Stichproben der echten Dienste vom 2026-10-09 liegen unter `.superpowers/sdd/2026-10-09-se-be/raw/` (git-ignoriert): `se_mais_*.json`, `se_DAIM_TOPO_*.json`, `se_dynais_NOTAM.json`, `se318.json`, `be_zones.json`. Fixtures für Tests sind **kleine, daraus abgeleitete Auszüge**, die ins Repo unter `tests/fixtures/` kommen (wenige Features je Fall, Koordinaten gekürzt) — nie die Rohdateien selbst.

## Review Focus

1. Belgien-Abfrage ohne wirksamen `TIME_ZONE`-Filter (149 MB in eine Function oder in den Workflow) → der Filter steht in jeder URL und ist getestet (Tasks 1–3).
2. Schweden: ein Layer fehlt oder liefert einen Fehler → kein Teil-Snapshot, alter Stand bleibt (Tasks 1, 2).
3. Schwedische Höhenangaben `GND`, Zahl in Fuß, `FL 95`, `UNL` → korrekt und ohne `NaN` in der Anzeige (Task 1).
4. Der verallgemeinerte NOTAM-Knopf darf Norwegen nicht verändern und in Ländern ohne Live-Quelle nicht erscheinen (Task 4).
5. Belgien-Hinweis fehlt oder ist nur in einer Sprache vorhanden → vier Aussagen der BCAA in allen fünf Sprachen, immer sichtbar (Task 4).
